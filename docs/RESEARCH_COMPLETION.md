## G03's original answer remains deferred

The question requires a complete worldwide listed-parent universe, consolidated after-tax income attributable to parents including losses, parent/cross-listing deduplication, exact fiscal periods and currencies/scales, filing/amendment availability and matched period FX. Only its world-GDP input currently satisfies the original contract. Public regulator sources can build samples; the checked evidence does not establish the exact worldwide total.

The older view called MSCI factsheet market capitalization divided by P/E aggregate earnings that companies “earned.” It now calls this an **implied index earnings proxy**. Its calculation and compatible API value keys are retained, with explicit machine-readable scope flags and the methodological boundary carried into the bundle, chart and export. The December proxy divided by world GDP is only an arithmetic comparison. [MSCI's fundamental methodology, sections 1.2.2 and 3.1](https://www.msci.com/indexes/documents/methodology/0_MSCI_Fundamental_Data_Methodology_20240625.pdf), establishes the normalized earnings, inclusion factors and missing-EPS exclusions that prevent the original interpretation.

The EU27 alternative is non-financial corporate gross operating surplus relative to sector value added. The OECD alternative is a reporting-country, GDP-weighted corporate gross operating-surplus/GDP construction, with country count and GDP coverage shown separately. Gross surplus is before depreciation; even net operating surplus remains before property-income flows and corporation tax. Neither is consolidated after-tax listed-company net profit. See [Eurostat sector-account definitions](https://ec.europa.eu/eurostat/cache/metadata/en/nasa_10_nf_tr_esms_at.htm) and the dashboard's [OECD corporate-surplus construction](OECD_CORPORATE_SURPLUS.md).

## Source paths that can be used honestly

Existing native routes can acquire another dated CVM annual archive, a current/explicitly located MSCI factsheet, supported SEC N-PORT filings and named issuer UCITS reports. They use `research structured` with a bounded task/request budget, immutable original archive, independent receipt and resumable journal. The read-only plan must precede an acquisition. A successful download still requires native parsing and scientific acceptance.

[SEC EDGAR APIs](https://www.sec.gov/search-filings/edgar-application-programming-interfaces) provide no-key entity-wide standard-taxonomy facts and filing histories, useful for an explicitly delimited filer panel. They exclude custom-taxonomy facts and do not provide a worldwide listed-parent census; mixed fiscal periods and duplicate cross-listings need explicit handling. [OECD–UNSD MEIP](https://www.oecd.org/en/data/dashboards/oecd-unsd-multinational-enterprise-information-platform.html) provides a top-500-MNE structure and 2024 indicators, including profits, as a sample. [GLEIF Level 2](https://www.gleif.org/en/lei-data/access-and-use-lei-data/level-2-data-who-owns-whom) supports parent links but does not supply a listing universe or income, and missing relationships cannot be treated as “no parent.”

Official [TWSE templates](https://openapi.twse.com.tw/) cover distinct general/financial sectors, while the current retained Taiwan reader has only general-business snapshots and correctly leaves annual-flow, currency/scale and full population unverified. A broader source needs the corresponding original definitions and filings, not an annualization guess.

The [ESMA ESEF toolkit](https://github.com/European-Securities-Markets-Authority/esef_toolkit) is a useful extraction reference; its interim repository has best-effort coverage. [ESAP](https://finance.ec.europa.eu/financial-markets/company-reporting-and-auditing/company-reporting/transparency-requirements-listed-companies_en) starts public access in 2027 and is not a current complete EU feed. Existing operator configuration contains EDINET/DART credential entries, but no canonical collector/host integration or validated access was established by this audit; no credential values were inspected or disclosed. [Japan's official EDINET documentation](https://disclosure2dl.edinet-fsa.go.jp/guide/static/disclosure/WZEK0090_001.html) confirms API v2 uses an issued key.

All future collection remains inside the single managed client, central host/rate registry and durable policy ledger. Do not spend money, invent contact identity, bypass refusal/authentication, retry an access-denied URL through another route, replace original evidence, fill absent history or relax acceptance. Publisher rights metadata stays visible independently of technical access and private collection eligibility. See [source policy](SOURCE_POLICY.md).
